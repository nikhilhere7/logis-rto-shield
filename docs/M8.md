# M8: report centre, plus removing and replacing uploaded data

Read this whole file before doing anything. This replaces the earlier M8 zip. If you already copied the
earlier M8 files, copy these over them; the steps are the same.

## What this adds

1. Report centre (backend app `reports/`, no models, nothing stored)
   - `GET /api/reports/` lists the five reports and whether this merchant has the data for each.
   - `GET /api/reports/<id>.pdf` builds one report. ids: `summary`, `returns`, `couriers`, `audit`, `customers`.
   - Every PDF has three parts: page 1 is an introduction (what logis is based on, what the report covers,
     the uploaded data behind it, how the numbers are worked out, a short glossary); then the report;
     the last page is the conclusion (what the data shows, what to do next, the limits of the report).
     The conclusion is written from the merchant's own numbers; a sentence only appears when the data backs it.
   - Look: white pages, navy and teal, one deep red for the worst value, the Inter typeface.
     The two Inter font files ship in `reports/fonts/` with their licence (SIL Open Font License).

2. Removing and replacing data (backend `ingestion/`)
   - `DELETE /api/ingestion/uploads/<id>/` takes an upload that was never loaded off the history.
     A loaded upload is refused, because its rows are in the workspace.
   - `POST /api/ingestion/data/remove/` with `{"kinds": ["shipments"], "confirm": "remove"}` removes one or
     more kinds of data; `{"kinds": "all", "confirm": "remove"}` empties the workspace. The ledger and audit are
     rebuilt afterwards. Removing orders also removes their shipments and customers. Removing orders or shipments
     switches the trained risk model off (orders are scored by rules until it is retrained).
   - Commit takes `{"replace": true}`: the rows of that kind already loaded are removed first, in the same
     transaction, and the new file takes their place. Without it, a new file adds to what is there, as before.
   - No models and no migrations.

3. Frontend
   - Reports page (replaces "coming soon").
   - Uploads page: a "Your data" panel with counts, a Remove button per kind (asks to confirm), and
     "Empty my workspace and start again" (needs the word remove typed). A × on uploads that were never loaded.
     When a kind is already loaded, the check step asks "Add to them" or "Replace them".
   - Risk checker: "Checked this visit" now has a × on each order and a "Clear all".

## How this was integrated here (differences from the steps above, all approved)

The zip was merged selectively, not copied wholesale: files already identical to the zip were left alone, and the
files below were changed on top of it.

Safety additions
- `backend/ingestion/cleanup.py`: stored upload and model files are deleted only after the transaction commits
  (`delete_file_after_commit`, using `transaction.on_commit`). "Start over" (`clear_everything`) runs as one
  transaction: either everything goes or nothing does.
- `backend/ingestion/views.py`: removing a never-loaded upload also defers its file deletion until after the commit.
- `backend/reports/views.py`: PDFs are sent with `Cache-Control: no-store, private`, and the file name comes from
  the server: `logis_<merchant>_<report>_<YYYY-MM-DD>.pdf`.
- `backend/config/settings.py`: `CORS_EXPOSE_HEADERS = ["Content-Disposition"]`, so the React app can read that name.
- `frontend-next/src/lib/api.js`: `download()` uses the server's file name (a generic name only if none is sent);
  `Reports.jsx` no longer builds a file name itself.
- `frontend-next/src/pages/Uploads.jsx`: "Replace them" shows a warning of everything that goes with the old rows
  (for orders: shipments, tracking, customers and products, and the risk model is switched off) and needs a tick
  box before the Replace button works. `replace: true` is sent only when that box is ticked.
- `frontend-next/src/components/YourData.jsx`: each Remove confirmation says exactly what else goes, and that the
  upload history goes and the ledger and audit are rebuilt.
- `backend/reports/build.py`: "1 charge" / "2 charges" agreement in the report sentences.

Extra tests
- `reports/test_reports.py`: file name and `Cache-Control` checked; two merchants each get PDFs with their own name
  and file name; a merchant id sent by the client is ignored.
- `ingestion/test_cleanup.py`: files are deleted only after the commit; a failure during start over rolls back
  every row and keeps every file; a replace that fails while loading keeps the old data; `replace` must be exactly
  `true`; a merchant id sent by the client is ignored. These use a temporary media folder.

Manual check 7 must only ever be done with a separate test merchant, never with real merchant data.
